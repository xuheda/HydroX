概述

HydroX 提供以下能力：

  • 状态估计：统一 18 维混合辅助 EKF，由 UUV、USV、UAV Profile 选择性融合 IMU、DVL、GPS、深度/水面约束、磁罗盘等观测。
  • 导航制导控制（GNC）：支持 slender-body AUV、ROV、USV、多旋翼、固定翼、VTOL 等多种载具。
  • 控制分配：将期望的 6 自由度广义力映射到具体执行机构（舵、螺旋桨、推进器阵列、旋翼等）。
  • MAVLink HIL 通信：与仿真器（如 OceanX/Unreal Engine）通过 MAVLink HIL 协议交互。
  • DDS/XRCE 桥接：通过 Micro XRCE-DDS 与 ROS 2 生态交换遥测和设定点。
  • XLog 日志：自研二进制时序日志格式，用于回放与诊断。

HydroX 被设计为可独立运行的程序（hydrox_sitl），也可以作为库被其他项目链接。

CMake 构建目标

目标类型说明
hydrox静态库核心自动驾驶仪库
hydrox_sitl可执行文件PC 端 SITL，使用 Host 平台适配与 TCP HIL
hydrox_pixhawk6c_hitl固件边界Pixhawk 6C / STM32H743 的 HITL-only 目标；真实 NuttX BSP 缺失时明确失败，不生成占位固件

hydrox_pixhawk6c_hitl.bin 是构建产物，不是仓库中的手写源码。Pixhawk 6C 专用代码统一放在 boards/pixhawk6c/；该目录仍需补齐固定版本的 NuttX 板级移植、兼容 bootloader 且经过实机验证的链接脚本、非阻塞 HIL/伴随计算机设备、定时器和 watchdog。条件未满足时配置会明确失败，不生成不可烧录的占位固件。

SITL 与 HITL 共用 HydroX runtime 的周期调度器和命令权限门控。SITL 注入 HostClock/HostSleeper，Pixhawk 6C 注入 NuttxClock/NuttxSleeper；连接代次、有效传感器就绪、旧命令拒绝、超时撤权和错过周期处理不允许在两个入口中分别实现。TCP、DDS、QGC 和 PC XLog 仍属于 SITL 集成层。

依赖：

  • Eigen 3.4+：线性代数，需手动克隆到 third_party/eigen。
  • Micro-CDR / Micro-XRCE-DDS-Client：CMake FetchContent 自动下载。
  • Apache NuttX 13.0.0：版本、下载地址和 SHA-512 固定在 third_party/nuttx.lock.json。
  • Threads / ws2_32 / bcrypt（Windows）或 OpenSSL（Linux）。

公共头文件

include/types.h

核心数据结构：

  • NavigationState：平台中性的 6 自由度位姿 eta、体坐标系速度 nu 和环境介质速度。
  • FinCmd：4 个舵角、RPM、推力分数，提供 clamp 和 normalize 方法。
  • IMUMeasurement、DVLMeasurement、DepthMeasurement、GPSMeasurement：传感器测量。
  • GNCMode：控制模式（DISABLED、DEPTH_HOLD、WAYPOINT_3D、DP、SURFACE）。
  • GNCSetpoint：深度、航向、前进速度、航点等设定值。
  • VehicleClass：载具类别（UUV、USV、多旋翼、固定翼、VTOL）。

include/estimation_profile.h

EstimationProfile 集中定义平台垂向辅助、DVL/GPS/磁罗盘观测门控、环境速度语义和 EstimatorTuning(Q/R/P0)。SITL 为 EKF 与 SensorAdapter 注入同一 Profile，避免两侧类别判断漂移。

include/ekf.h

class EKF：18 维混合辅助扩展卡尔曼滤波器。

状态向量：

[N, E, D, roll, pitch, yaw, u, v, w, b_ax, b_ay, b_az, b_gx, b_gy, b_gz, m_N, m_E, m_D]
  • 位置 / 姿态 / 体坐标系速度
  • 加速度计零偏、陀螺零偏
  • NED 坐标系下环境介质速度：水流或预留风速

测量更新包括：

  • 底跟踪 DVL 速度
  • 水跟踪 DVL 速度
  • 零速度伪测量
  • 深度
  • GPS 位置 / 速度
  • 磁罗盘 / 真值航向
  • 加速度计水平对准

include/sensor_adapter.h

class SensorAdapter：将 MAVLink 帧解析为 NavigationInput。

  • ingest_frame()：按 msg_id 分派。
  • build()：计算时效性、协方差、GPS 地心地平坐标转 NED、判断加速度计是否可用。

include/mavlink_hil.h

手写 MAVLink 2 编解码器，不依赖 pymavlink/mavlink C 库。

支持的消息：

  • 输入：HIL_SENSOR、HIL_GPS、HIL_DVL、HIL_TRUTH_STATE、自定义 OceanX 传感器消息。
  • 输出：HIL_ACTUATOR_CONTROLS、HEARTBEAT。
  • QGC 遥测：ATTITUDE、LOCAL_POSITION_NED、VFR_HUD、GLOBAL_POSITION_INT、SYS_STATUS、STATUSTEXT。

include/transport.h / include/tcp_transport.h

  • Transport：抽象接口。
  • TcpTransport：跨平台 TCP socket，支持客户端/服务器模式、非阻塞 I/O。

include/xlog_writer.h

XLog 1.0 二进制日志格式。

  • 主题：HydroxState、HydroxSetpoint、HydroxControlError、HydroxControllerOutput、HydroxActuator、HydroxEstimatorHealth、HydroxTiming、SimulatorTruth、DeploymentAlignment。
  • Writer：分块、CRC32 校验、分段文件写入。

核心源文件

src/ekf.cpp

EKF 完整实现：

  • _predict()：状态传播与协方差数值雅可比传播。
  • _update_*()：各类传感器的测量更新。
  • 创新卡方（NIS）门控，防止异常值污染。
  • 水流状态通过水跟踪 DVL 与 GPS 地速联合估计。

src/sensor_adapter.cpp

  • 分派 MAVLink 帧。
  • GPS 地心地平转局部 NED。
  • 区分底跟踪与水跟踪 DVL。
  • 根据 fields_updated 判断加速度计、磁力计是否有效。
  • 根据 EstimationProfile 选择压力深度、水面约束或 GPS 高度，并拒绝平台不适用的观测。

src/mavlink_hil.cpp

  • CRC-16/MCRF4XX + CRC_EXTRA，与 PX4 兼容。
  • 支持 MAVLink 2 签名验证与签名输出。
  • 自定义 OceanX 传感器消息解析。

src/mavlink_signing.cpp

  • 从十六进制文件加载 32 字节密钥。
  • 使用 Windows BCrypt 或 OpenSSL 计算 SHA-256 摘要。
  • 常量时间签名比较。

src/fossen_vehicle_params.cpp

  • 手写轻量 JSON 解析器（不依赖外部 JSON 库）。
  • 兼容读取调用方显式传入的旧 JSON 文件或目录；新集成使用 VehicleBundle。
  • 内置 EcaA9、LAUV、DesistekSaga、RexROV2、Otter、WAMV、X500、RCCessna、StandardVTOL 等回退参数。
  • 用长球体 Lamb 因子计算附加质量惯量。

src/xlog_writer.cpp

  • CRC32、FNV-1a64 schema 哈希、JSON 转义。
  • 文件头、元数据、schema、块、页脚的写入。
  • 按目标块大小和最大段大小自动分段。

SITL 运行时

apps/sitl/main.cpp

SITL 主程序使用 HostClock、HostSleeper、共享 PeriodicScheduler 和 ControlSessionGate 运行默认 100 Hz 控制循环：

  1. 解析命令行配置。
  2. 初始化网络、父进程守护、MAVLink 签名、载具参数、控制栈。
  3. 外层循环：连接 UE5 TCP，建立新的控制会话代次，断线后撤权并重连。
  4. 内层循环（rate_hz）：
    • 读取 MAVLink 字节，送入 SensorAdapter。
    • 只有收到本次连接代次的有效传感器后才允许接受新设定点。
    • 处理仿真器暂停（MAV_STATE_STANDBY）并保持心跳。
    • 消费 DDS 连接状态与设定点，按 DDS 和 HIL 会话代次过滤。
    • 按平台单调时间检查设定点超时并进入安全 DISABLED 状态。
    • EKF 更新。
    • 控制器更新 → 分配器 → 执行器命令。
    • 电机模型、能量模型。
    • 发送 HIL_ACTUATOR_CONTROLS。
    • 发布 DDS 遥测。
    • 发送 QGC 遥测（4 Hz）和 SYS_STATUS（1 Hz）。
    • 写入 XLog。
    • 由共享周期调度器等待下一 release time；迟到时跳过已错过周期，不忙等追赶。

src/sitl/sitl_config.cpp

命令行配置解析，包括 UE5/QGC/DDS 地址、载具类型、EKF 模式、XLog 路径、初始状态、任务半径/超时等。

src/sitl/sitl_platform.cpp

  • NetworkRuntime：Windows 初始化 Winsock；Linux/POSIX 使用原生 socket，无需显式初始化。
  • ParentProcessGuard：父进程退出时终止 SITL，Windows 使用进程句柄，Linux/POSIX 使用 PID 检查。
  • UdpSender：QGC 广播 UDP。

src/sitl/dds_worker.cpp

后台线程拥有所有 XRCE-DDS 操作：

  • 通过 LatestValueMailbox 与 GNC 线程交换遥测、设定点、连接状态。
  • 断线重连，指数退避。
  • 设定点加盖 XRCE 会话代次戳，并使用注入的 platform::Clock 记录本地接收时间。

src/sitl/sitl_xlog.cpp

XLogRecorder：每控制周期组装一次记录，包括状态、设定点、力矩、执行器、导航、EKF，写入 XLog。

通信层

MAVLink HIL

SITL 通过 MAVLink HIL over TCP 与仿真器通信；Pixhawk 6C HITL 将通过 UART/USB 字节流承载同一消息契约。协议解析和控制逻辑不应依赖具体传输。

输入：

  • HIL_SENSOR：IMU、深度。
  • HIL_GPS：GPS。
  • HIL_DVL：DVL 体坐标系速度。
  • HIL_TRUTH_STATE：仿真器真值。
  • 自定义 OceanX 传感器消息。

输出：

  • HIL_ACTUATOR_CONTROLS：归一化执行器输出。
  • HEARTBEAT：1 Hz。

QGC 遥测：

  • ATTITUDE、LOCAL_POSITION_NED、VFR_HUD、GLOBAL_POSITION_INT @ 4 Hz。
  • SYS_STATUS @ 1 Hz。

Micro XRCE-DDS

GNC 线程 -> LatestValueMailbox -> DDS worker 线程 -> DdsPublisher -> UDP -> MicroXRCEAgent -> ROS 2
ROS 2 设定点 -> MicroXRCEAgent -> UDP -> DdsPublisher -> callback -> LatestValueMailbox -> GNC 线程

话题清单见 include/dds_topic_manifest.h，包括：

  • vehicle_local_position、sensor_combined、actuator_outputs
  • vehicle_status、state_estimate、truth_state、odom、tf
  • setpoint、passive_sonar_bearing、acoustic_neighbors、rangefinder_scan

VehicleBundle 控制契约

新集成使用显式的、版本化 VehicleBundle：

  • profiles/<bundle>/vehicle-bundle.json：控制构型、控制导向模型和逻辑执行器布局。
  • Bundle 不包含仿真器工程路径、SDF/URDF 资产或板级 PWM/CAN 映射。
  • 多推进器布局直接传入 ThrusterMatrixAllocator，不再依赖命名车型的硬编码布局；加载时报告有效性矩阵秩和逻辑通道数。
  • fossen_vehicle_params 仍保留为旧 JSON 的兼容加载器，但必须由调用者显式提供文件或目录。

详见 VehicleBundle 控制契约。

惯量归一化增益

控制器增益按载具惯量缩放：

  • 俯仰/偏航力矩环按 M44_pitch 缩放。
  • 前进力环按 mass_total 缩放。

这样不同载具可获得相似的闭环动态响应。

关键设计模式

策略模式

IController 和 IAllocator 把控制律与执行器布局解耦。

工厂模式

build_control_stack() 根据载具构型组装控制器和分配器。

适配器模式

SensorAdapter 把原始 MAVLink 帧转换为类型化的 NavigationInput。

非阻塞线程边界

  • 没有新传感器输入时，SITL transport boundary 可以等待 socket 可读；该等待不推进控制状态。
  • 收到输入后，单次 GNC 更新不等待 DDS，执行完成后立即返回执行器输出。
  • LatestValueMailbox 在线程间传递最新值。
  • DDS worker 在后台线程执行所有 XRCE-DDS I/O。

帧原子传输

NonblockingFrameSender 保证部分发送的帧尾在新帧之前完成，背压下仅丢弃完整未发送的帧。

会话门控

DDS 与 HIL 链路均使用会话代次。共享 ControlSessionGate 要求每次连接先收到有效传感器，再接受该代次的新命令；断线、DDS 会话变化或平台单调时间超时都会撤销控制权限，旧命令不能跨重连恢复控制。

输入时间戳调度

HydroX 控制核心不按部署环境选择调度模式。每个严格递增的输入 timestamp 恰好推进一次估计、制导、控制和分配，相邻 timestamp 之差构成算法 dt；没有新 timestamp 时不推进控制状态。平台单调时钟统一用于连接、通信权限、heartbeat 和 watchdog，不替代输入时间戳。

与 OceanX 的集成

OceanX 通过 Git Submodule 引用 HydroX：

OceanX/
├── HydroX/          # submodule -> https://github.com/xuheda/HydroX
├── engine/          # Unreal Engine 项目
├── ros/             # ROS 2 包
└── ...

构建 OceanX 前：

git submodule update --init --recursive
cd HydroX
git clone --depth 1 --branch 3.4.0 https://gitee.com/mirrors/eigen.git third_party/eigen

然后运行 OceanX 的构建脚本，会调用 HydroX/build_sitl.bat 编译 hydrox_sitl.exe 并部署到 engine/Binaries/ThirdParty/HydroX/。

HydroX 与 OceanX 之间仅通过 MAVLink HIL 协议 通信，因此两者可以独立开发、独立版本发布。
