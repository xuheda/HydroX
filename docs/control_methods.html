HydroX 底层控制方法与自由度耦合分析

更新日期：2026-07-28

返回 HydroX 文档首页 · OceanX 集成文档

本文记录 HydroX 自驾仪 gnc 模块各载具原型(archetype)采用的底层控制方法, 以及每种原型的六自由度(6-DOF)驱动/耦合情况。高层职责边界见 控制架构，ROS/DDS 接口见 OceanX ROS 2 话题与接口契约，动力学模型见 OceanX 载具动力学与接入。

1. 控制契约:tau-合同

整个控制栈围绕一个广义力契约解耦"控制律"与"执行器布局" (见 control_interfaces.h):

IController :  state + setpoint  ->  Wrench tau = [X, Y, Z, K, M, N]
IAllocator :  tau               ->  ActuatorCmd (归一化 [-1,1] 通道)
  • tau:机体系 NED 广义力/力矩,[X, Y, Z, K, M, N](N、N·m)。
  • 控制律只知道如何产生 tau(且只填它能驱动的那几个分量)。
  • 分配器只知道如何把 tau 映射到具体执行器,耦合在这一层被几何解算。

一个载具 = 一个 IController 原型 + 一个 IAllocator 布局,由载具 profile 在 control_factory.cpp 中装配。状态定义见 types.h:eta=[N,E,D,roll,pitch,yaw]、 nu=[u,v,w,p,q,r]。

3. SlenderBodyAUV — 鱼雷型 AUV(级联 + 滑模)

源码:gnc_controller.cpp、 control_allocator.cpp。

细长体 AUV 欠驱动:只有尾部螺旋桨 + 十字/X 尾舵,无法直接产生侧向力、 垂向力或滚转力矩。它只填 tau 的 3 个分量:X(纵荡)、M(俯仰)、N(艏摇)。

3.1 三条控制回路

回路方法文件输出
纵荡 XP/PI 速度控制(实为带抗饱和的 PID)surge_p.htau_X
深度→俯仰级联:外环深度 PID,内环俯仰 PIDdepth_pid.cpp / pitch_pid.htau_M
艏摇 N积分滑模(SMC) 或 偏航角速率跟踪 PI+前馈heading_smc.cpptau_N

这三条回路共同回答一个问题:细长体 AUV 只能有效驱动 X/M/N,那么控制器应该如何把任务误差 转成这三个广义力分量。纵荡环负责“快慢”,深度-俯仰级联负责“上浮/下潜”,艏摇环负责“朝向”。 控制律只输出 tau_X/tau_M/tau_N;具体舵角、桨速由后面的 FinAllocator 处理。

纵荡 X:速度误差 -> 前向力 tau_X

纵荡环控制的是机体系前向速度 u。上层给出期望速度 surge_ref,传感/状态估计给出当前速度 surge,控制器先形成速度误差:

e_u = surge_ref - surge

SurgeP 名字里虽然是 P,实际是带工程保护的速度 PID:

tau_X = drag_ff·surge_ref·|surge_ref| + kp·e_u + ki·∫e_u dt - kd·surge
  • kp·e_u:速度低于目标时给正推力,速度高于目标时减推或制动。
  • ki·∫e_u dt:补偿稳态阻力,避免长期低于目标速度。
  • -kd·surge:用当前速度做阻尼,抑制过冲。
  • drag_ff·v|v|:把水阻主要项提前补进去,让积分项只负责修正误差。
  • 积分限幅、误差变号退绕、超速制动和推力斜率限制用于处理执行器饱和与速度切换。

所以纵荡链路是:

surge_ref, surge -> 速度 PID/阻力前馈 -> tau_X -> 螺旋桨转速

它是整条鱼雷型 AUV 控制链的基础,因为尾舵舵效依赖动压 q∝u²;没有足够前向速度, 后面的俯仰和艏摇舵控都会变弱。

深度 -> 俯仰:深度误差 -> 期望俯仰角 -> 俯仰力矩 tau_M

细长体 AUV 通常没有独立垂向推进器,不能像 ROV 那样直接输出 tau_Z 来定深。它的定深机理是: 先让艇产生合适的俯仰角,再利用前进速度和舵面升力改变下潜/上浮趋势。因此这里采用两级闭环:

depth_ref, depth, heave_rate
    -> 外环 DepthPID
    -> theta_ref(期望俯仰角)
    -> 内环 PitchPID
    -> tau_M
    -> 水平舵差动

外环先用三阶参考模型把 depth_ref 平滑成内部参考 _ref.xd/_ref.vd,避免深度命令阶跃导致 俯仰角突变。然后计算:

e_z     = depth - depth_ref_smooth
e_z_dot = heave_rate - depth_rate_ref_smooth
theta_ref = kp·e_z + kd·e_z_dot + ki·∫e_z dt

这里的输出不是力,而是期望俯仰角 theta_ref。如果当前深度比目标浅,外环会给出一个下潜方向的 俯仰角;如果当前深度比目标深,则给出上浮方向的俯仰角。theta_ref 会被 theta_max≈15° 限幅, 避免为了追深度而要求过大的姿态。

内环再让真实俯仰角 pitch 跟踪 theta_ref:

e_theta = theta_ref - pitch
tau_M = kp·e_theta - kd·pitch_rate + ki·∫e_theta dt

也就是说,外环回答“为了修正深度,艇头应该抬/压多少”,内环回答“为了达到这个俯仰角,水平舵应该 产生多大俯仰力矩”。近水面时 theta_ref 会渐隐,避免艇在水面附近被控制器强行压下去。

艏摇 N:航向/角速率误差 -> 偏航力矩 tau_N

艏摇环有两种工作方式。普通航向保持时,目标是让当前航向 heading 跟踪 heading_ref; 策略如果直接给角速率,则切到 yaw-rate 跟踪。

航向保持使用积分滑模控制。它先通过三阶参考模型把 heading_ref 平滑成期望航向和期望角速率, 再计算航向误差和角速率误差:

e_psi = ssa(heading_ref_smooth - heading)
e_r   = yaw_rate_ref_smooth - yaw_rate

ssa() 把角度误差折回 [-π, π],避免例如 359° -> 1° 被误判成大转弯。然后构造滑模面:

sigma = e_r + kd·e_psi + ks·ei        (滑模面,带积分项)
ei = ∫e_psi dt

滑模面的含义是把“航向误差、角速率误差、长期偏差”合成一个收敛指标。控制器希望 sigma -> 0: 只要 sigma 不为零,就给一个把系统推回滑模面的偏航力矩。实际输出为:

tau_N = T·(wn·e_r - kd·r)/K + ks·sat(sigma/phi_b)/K
  • 前半项来自一阶 Nomoto 转艏模型的逆模型/前馈,用于给出预期转艏所需力矩。
  • 后半项 sat(sigma/phi_b) 是滑模反馈,用于抵抗水动力参数误差和外界扰动。
  • 使用 sat() 边界层而不是硬符号函数,是为了减少滑模控制常见的抖振。

所以航向链路是:

heading_ref, heading, yaw_rate -> 参考模型/SMC -> tau_N -> 垂直舵差动

当 setpoint 为 use_yaw_rate_ref 时,控制目标从“到某个航向角”变成“跟踪某个偏航角速度”。 这时控制器使用 PI + 前馈:先对角速率参考做一阶滤波和斜率限制,再用角速率误差积分消除 稳态偏差,同时用前馈提高响应速度。

Nomoto 与 Fossen 的关系:控制用低阶模型 vs 动力学真模型

Nomoto 模型来自 Nomoto 等人的船舶操纵性研究,本质上是一类面向操纵控制的低阶线性模型。 它不只可以写艏摇;在完整操纵性建模里,水平面可以包含横荡-艏摇 v/r,垂直面也可以包含 垂荡-俯仰 w/q。这些模型都是从更完整的船体水动力方程在某个工作点附近线性化、降阶或 辨识得到的。

本控制器当前使用的是其中最常见、最轻量的一阶转艏 Nomoto 形式,只把“控制输入如何影响 偏航角速度 r”抽出来作为艏向控制的内部模型:

T·r_dot + r = K·delta        (舵角输入形式)
T·r_dot + r = K·tau_N        (等效艏摇力矩形式)

其中 T 是转艏时间常数,K 是转艏增益。它是线性模型,适用于固定航速附近、小舵角、 小侧滑/小扰动的工作点;真实舵效、横荡-艏摇耦合、垂荡-俯仰耦合和非线性阻尼等影响, 在一阶转艏形式里被压缩进 T/K 或被外层反馈吸收。

Fossen 模型不是被 Nomoto 替代。OceanX 的主动力学仍是完整 6DOF Fossen 方程:

M·nu_dot + C(nu_r)·nu_r + D(nu_r)·nu_r + g(eta)
  = tau_control + tau_environment

因此二者的关系是解耦的模型分层:

HeadingSMC 内部: 用 Nomoto 逆模型估计需要的 tau_N
FinAllocator   : 把 tau_N 分配成垂直舵差动
Fossen 6DOF    : 接收执行器 wrench,积分得到真实 yaw_rate/heading
反馈           : Fossen 状态再回到控制器

可以把 Nomoto 看成控制器的“脑内简化模型”,把 Fossen 看成仿真/实艇侧的被控对象模型。 控制器不需要背完整 Fossen 6DOF 方程,只需要通过 tau_N 接口提出艏摇力矩需求;Fossen 则负责 真实的附加质量、阻尼、耦合、浮力和环境扰动响应。如果 Nomoto 的 T/K 和 Fossen 的实际响应 有偏差,滑模反馈项会补偿一部分模型误差。若航速范围很大,更好的做法是从 Fossen 阶跃响应或 实艇试验中辨识 T/K,甚至做成速度调度参数 T(u), K(u)。

结论上,这不是“所有 AUV 都通用的唯一最优解”:如果艇型变成悬停 ROV、全驱动多推进器平台, 深度控制就应该直接走 tau_Z;如果追求强约束最优轨迹,可以进一步引入 MPC。但对本节描述的 SlenderBodyAUV,这三环就是当前最匹配的工程控制组合,后续优化应优先围绕前馈、速度调度、 抗饱和和分配器约束展开,而不是轻易推翻这套闭环结构。

3.2 FinAllocator — 舵/桨分配

control_allocator.cpp 把 tau 反解为舵偏与转速:

  • 螺旋桨:tau_X → 转速,n = sign·√(|tau_X|/kT),kT = KT_0·ρ·D⁴。
  • 水平舵(ss/ps):由动压 q = ½ρu² 反解 delta_z(垂向力)与 delta_m(俯仰),

以差动叠加:delta_ss=(delta_z+delta_m)/2、delta_ps=(delta_z-delta_m)/2。

  • 垂直舵(br/tr):由 tau_N 反解 delta_r,差动:delta_br=delta_r/2、delta_tr=-delta_r/2。

注意舵效正比于动压 q∝u²:低速时除以 q 会放大舵偏 → 舵权丧失。这是纵荡速度与 俯仰/艏摇舵权之间的关键耦合(见 §8)。

3.3 惯量归一化增益

fossen_vehicle_params.cpp 的 apply_inertia_normalized_gains 以参考载具(M44=25.68, mass=71.5)为基准缩放增益: 俯仰/偏航增益 ×M44/25.68,纵荡增益 ×mass/71.5。这样不同体量的 AUV 获得一致的闭环响应。

3.4 面向物理参数的逐车调参

不同 AUV 的质量、惯量、舵面积、力臂、螺旋桨能力和水动力阻尼不同，控制参数不能被当作与载具无关的常数。OceanX 使用与 UE Fossen 主积分相同的参数源：

engine/Content/Fossen/<vehicle>_params.json

推荐流程：

载具几何、惯量、水动力和执行器参数
  -> 按 mass / pitch inertia 生成归一化基线
  -> 选择 settling time、damping ratio、姿态和舵面饱和预算
  -> 运行固定 depth / heading / surge maneuver
  -> 评估跟踪误差、瞬态峰值、收敛时间和执行器饱和
  -> 必要时写入 vehicle-specific control override

物理限制包括舵面面积/最大偏角、升力斜率、推进器推力/RPM、质量、惯量和阻尼；depth.theta_max、pitch.kp/kd、heading.wn/kd、surge.kp 等属于控制器响应和保护参数。theta_max 是 depth 外环允许输出的最大俯仰命令，不是载具姿态硬限制。

闭环调参至少记录：

指标含义
depth_err / depth_peak稳态和瞬态深度误差
w_peak / pitch_peak垂向速度和最大俯仰角
fin_sat舵面接近饱和的样本比例
heading_err稳态航向误差
surge稳态纵荡速度
dvl_valid速度估计输入是否有效

调参必须检查 sensor → estimator → controller → allocator → actuator 整条链路。EcaA9 曾出现的俯仰振荡和 surge 异常并非纯增益问题：DVL 无效会触发零速度伪观测，先修复测量/估计有效性后才有意义继续调节控制 override。工程目标是“physics-aware initialization + simulation-metric-guided calibration”，不是宣称全局最优自动调参。

4. Thruster — ROV / 悬停 AUV(逐轴 PD + 矩阵分配)

源码:thruster_controller.cpp、 thruster_allocator.cpp。

矢量推进 ROV 全驱动或过驱动,可独立控制 6 个轴。控制律是逐轴解耦的 加速度级 PD,再乘以载具质量得到力/力矩:

accel = clamp(kp·err - kd·rate, accel_max);   tau_axis = mass · accel
轴默认增益 {kp,kd,accel_max}行为
纵荡 X{0.6, 0.8, 2.0}跟踪 surge_ref
横荡 Y{0.0, 0.5, 1.0}纯阻尼(把横向速度压到 0)
垂荡 Z{0.6, 1.6, 3.0}直接垂向推力定深
滚转 K{0, 0, 0}默认被动(关闭)
俯仰 M{0, 0, 0}默认被动(关闭)
艏摇 N{1.0, 1.2, 2.0}定向或角速率跟踪

与细长体 AUV 截然不同:深度由直接垂向推力(Z)实现,而非俯仰。滚转/俯仰默认 增益为 0——多数 ROV 因 CoB 高于 CoG 而被动稳定,欠驱动型(如 DesistekSaga 仅 3 个推进器, 只能产生 surge/yaw/heave)根本无法产生滚转/俯仰力矩,强行指令只会与分配器对抗。

ThrusterMatrixAllocator 是真正解算耦合的地方。它由各推进器的位置/方向构造 6×n 配置矩阵 B,用阻尼最小二乘伪逆分配:

B 的第 i 列 = [ dir_i ; pos_i × dir_i ]      (单位推力 -> 机体 wrench)
u = Bᵀ (B Bᵀ + λI)⁻¹ tau                    (每个推进器的推力)

由于每个推进器同时贡献力与力矩,轴间耦合在伪逆中被自动分配。三种布局在 control_factory.cpp 中给定: 8 推进器矢量布局、DesistekSaga(3 推)、RexROV2(6 推)。

5. Surface — 水面无人艇(纵荡 + 艏摇 PD)

源码:surface_controller.cpp、 surface_allocator.cpp。

水面艇是经典的 3-DOF 欠驱动(平面运动 surge/sway/yaw,但只驱动 surge 和 yaw):

  • 纵荡:tau_X = surge_kp·(surge_ref - u) - surge_kd·u,增益 `surge_kp=3·mass,

surge_kd=1·mass`。

  • 艏摇:航向 PD tau_N = yaw_kp·ssa(psi_ref-psi) - yaw_kd·r,或角速率跟踪。
  • 横荡(Y)不控——靠艏摇间接对准。WAYPOINT_3D 模式下用 LOS 视线法

heading_ref = atan2(dE, dN),并按剩余距离限制 surge_ref。

TwinScrewAllocator 双桨差动:

port      = 0.5·X - 0.5·N/lever
starboard = 0.5·X + 0.5·N/lever

纵荡来自双桨共模,艏摇来自双桨差模——这是欠驱动水面艇标准的 surge/yaw 解耦方式。

6. Multirotor — 四旋翼(位置→姿态级联)

源码:multirotor_controller.cpp、 multirotor_allocator.cpp。

四旋翼 欠驱动(4 个执行自由度驱动 6-DOF),水平移动必须靠倾转机体实现, 因此采用位置→姿态级联:

水平位置误差 --[xy PD]--> 期望加速度 --[/g, 旋转到机体]--> roll_ref / pitch_ref
                                                  |
高度误差 --[z PD]--> 总拉力 tau[2]                 v
                                          姿态 PD --> tau[3](K), tau[4](M)
航向/角速率 --[yaw PD]--> tau[5](N)
  • 高度:tau[2] = mass·(g - z_accel_down),z_accel_down 由 z 轴 PD 限幅得到。
  • 倾转耦合(显式):pitch_ref = -acc_forward/g、roll_ref = acc_right/g,均限幅到

max_tilt_rad。这正是"前进需低头、右移需右滚"的平移-姿态耦合。

  • 所有轴乘 mass。

QuadrotorAllocator 标准混控:FL=T-R-P-Y, FR=T+R-P+Y, RR=T+R+P-Y, RL=T-R+P+Y, 即拉力(共模)+ 滚转/俯仰/偏航(差模)叠加到四个电机。

7. FixedWing — 固定翼(倾斜转弯)

源码:fixedwing_controller.cpp、 fixedwing_allocator.cpp。

固定翼强欠驱动,采用倾斜转弯(bank-to-turn):

  • 高度 → 俯仰参考:pitch_ref = clamp(-altitude_kp·d_err + altitude_kd·w, ...)。
  • 航向 → 滚转参考:roll_ref = clamp(course_kp·ssa(heading_ref - psi), ...)——

航向与滚转耦合:改变航向必须先压坡度,而非直接用方向舵。

注意此原型中 tau 被复用为归一化执行器需求(非物理力):X=速度目标, K=滚转目标,M=俯仰目标,N=偏航角速率。FixedWingAllocator 据此直接映射到舵面: 升降舵=kp·pitch、副翼=kp·roll、方向舵=kp·yaw_rate、油门=trim+kp·(speed-surge)。

8. 自由度耦合总览

8.1 各原型 6-DOF 驱动矩阵

8.2 耦合机理分类

  1. 欠驱动耦合(间接达成)
    • AUV:深度 ← 俯仰 + 速度产生的舵升力(tau_Z=0,靠 M+X 实现 Z)。
    • 多旋翼:水平移动 ← 机体倾转(X←M、Y←K)。
    • 固定翼:转向 ← 滚转(N←K);爬升 ← 俯仰(Z←M)。
    • 水面艇:对准航向 ← 艏摇(Y 不可控)。
  1. 级联耦合(刻意构造)
    • AUV 深度回路:深度 → 俯仰角 → 俯仰力矩,外环输出是内环参考。
    • 多旋翼:位置 → 倾角参考 → 姿态力矩。

两者的外环都通过设定姿态参考驱动内环,深度/位置与姿态因此强耦合, 且共享同一组执行器(AUV 的 ss/ps 水平舵同时承担深度与俯仰)。

  1. 速度依赖耦合(气/水动力)
    • AUV 舵效 ∝ 动压 q=½ρu²。低速时 FinAllocator

除以 q → 舵偏饱和、俯仰/艏摇舵权丧失。纵荡速度直接调制俯仰与艏摇的可控性。

  • 固定翼同理:油门/空速决定舵面权限。
  1. 分配级耦合(几何解算)
    • ROV:每个推进器同时产生力与力矩,轴间耦合由 B 矩阵伪逆

u = Bᵀ(BBᵀ+λI)⁻¹τ 自动分配/解耦,阻尼项 λ 在接近奇异布局时保证数值稳定。

  • 舵机/双桨:通过差动把单一物理量拆成两个轴(ss/ps→深度+俯仰,

br/tr→艏摇,port/starboard→纵荡+艏摇)。

  1. 转弯-速度耦合(AUV 专有补偿)
    • 急转弯会因诱导/侧滑阻力掉速。turn_compensated_surge_ref 在硬转弯时下调内环

速度参考以贴合训练环境;另有按 |r|·v_ref² 的转弯阻力前馈(当前 kTurnDragFF=0 已禁用,见 gnc_controller.cpp 的说明:该前馈会把速度顶到 ~4.6 m/s 致观测越界、策略 OOD)。

8.3 设计要点

  • 耦合住在两层:控制律层(级联与交叉参考)与分配层(效率矩阵/差动)。新增几何

只需新增 IAllocator,控制律不变;新增可控自由度才需要新控制律。

  • 不在 UE 侧加 PID 或奖励逻辑;坐标变换只在 MAVLink/DDS/ROS 边界做

（见 控制架构。）
