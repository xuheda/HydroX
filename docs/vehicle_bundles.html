VehicleBundle 控制契约

更新日期：2026-09-25

返回首页 · SITL/HITL 契约

VehicleBundle 是 HydroX 唯一的运行时控制配置。仅支持 schema_version 字符串 2.0，不支持旧 schema、旧仿真参数文件或缺项回退。

配置放在哪里

全部 19 套配置位于 profiles/<车型>/vehicle-bundle.json，包括 EcaA9、LAUV（各含 test 版本）、DesistekSaga、RexROV2、BluffBodyROV、Otter、WAM-V、X500、RCCessna、StandardVTOL、R1Rover 及六套 generic 配置。

hydrox_sitl --vehicle-bundle profiles/eca-a9/vehicle-bundle.json
hydrox_control_shadow --vehicle-bundle profiles/eca-a9/vehicle-bundle.json --xlog flight.xlog --output report.csv

--vehicle-params 和 --vehicle-params-dir 已删除。OceanX 的 vehicle profile 必须用 control_bundle 显式引用文件，不能靠 vehicle_type 猜测控制参数。

Schema 2.0

根字段为 schema_version、id、control_contract、archetype、vehicle_class、control_model。多推进器构型还必须声明 actuator_layout。完整可运行示例请直接使用 profiles 中的文件；下列路径是结构说明，不是可省略字段的模板。

  • control_contract 必须为 hydrox.control/<archetype>@2。
  • archetype：slender_body_fin、thruster、surface、multirotor、fixed_wing、vtol、differential_drive。
  • vehicle_class 分别为 uuv、uuv、usv、uav_multirotor、uav_fixed_wing、uav_vtol、ugv_differential。
  • control_model.mass_kg 是各构型的控制质量估计量；pitch_inertia_kg_m2 仅属于尾舵式 AUV，其他构型不接受此字段。motor 提供运行时电机模型参数。
  • VTOL 必须分别配置 elevator_gain_inv_Nm、aileron_gain_inv_Nm、rudder_gain_inv_Nm；零表示关闭对应舵面控制，负数无效。不再接受共享 surface_gain_inv_Nm 或负数回退约定。
  • control_model.controller 包含该构型全部控制参数；fin 下分 depth、pitch、heading、surge、yaw_rate、turn_speed，其他构型为直接参数对象。
  • control_model.allocator 包含 fin / fixed_wing / vtol / differential_drive 的分配参数。尾舵安装角使用 allocator.fin_angles_deg，长度固定为 4。
  • surface 直接声明 channel_surge_limit_n 和 channel_lever_arm_m；升力载具直接声明总升力和力臂；不会在加载时从机型名推算。
  • thruster 的 actuator_layout.kind 为 thrusters 或 body_wrench。前者每项必须提供 position_m、direction_body（FRD 三维向量）、max_thrust_n，最多 8 路。

参数使用 SI 单位，明确带 deg、rpm 的字段除外。完整必填字段由 include/control_parameter_fields.h 定义。重复的质量和 VTOL 升力分配参数不在 controller/allocator 内再次存储。

边界与验证

Bundle 只属于飞控。仿真器保留视觉资源、碰撞、完整水动力/气动力/地面动力学；板卡保留输出引脚映射。OceanX 物理模型文件已删除冗余 control 段，修改物理模型不会自动覆盖已标定的控制参数。

必填字段缺失、未知或不适用字段、类型错误、重复 JSON 键、非有限数、版本/控制契约不匹配均拒绝加载。正质量、推力、力臂等必要约束也参与验证；欠驱动推进器布局报告警告，不虚构不存在的自由度。

所有有效增益均显式存储，不再执行旧的惯量增益缩放。test_vehicle_bundle 保存迁移前有效参数和确定性控制输出，用于验证 19 套配置未改变原有控制结果；test_hitl_profile_registry 对比文件加载和固件内嵌同一配置的输出与布局。

固件更新

FMUv6C 目前编译 10 套配置，均由 tools/generate_fmuv6c_profile_registry.py 从 Bundle 生成。运行 --check 可检测生成文件是否过期。注册表使用原始文件字节指纹，配置变化后必须重新生成并构建、刷写固件。旧指纹不能继续接入新配置。

本次迁移不改变安全策略，也不意味着每款载具已通过真实硬件或闭环航行验证。
