Purpose

The shipped vehicle parameters are conservative baseline values for repeatable waypoint following in the three-domain demonstration. They are intended for integration, mission, and UI validation rather than aggressive handling or system-identification work.

Parameter Loading Contract

HydroX loads each platform from one vehicle parameter file. Marine profiles live in engine/Content/Fossen; air profiles live in engine/Content/Aero. When a caller supplies Content/Fossen as the parameter directory, the loader also checks its sibling Content/Aero directory. This preserves the existing SITL invocation while making X500, RCCessna, and StandardVTOL profile-specific control tuning available at runtime.

The root control object holds controller gains and limits. Its archetype groups are thruster, surface, multirotor, fixedwing, and vtol. The slender-body AUV profiles retain their existing gnc group. The controller factory takes its default values only when the matching control group is absent; a loaded group is the runtime source of truth.

For ROVs, thruster caps remain separate from axis gains: the physical cap is actuators.max_thrust_per_thruster_N, while control.thruster defines the surge, sway, heave, roll, pitch, and yaw response. Unactuated axes are set to zero explicitly rather than relying on a misleading nonzero gain.

Baseline Sweep

demo/showcases/control_baseline.json starts all eight per-vehicle planners, waits strictly for state/action readiness, and sends non-conflicting looping routes. Use it after bringing up the three-domain scenario:

demo_showcase.bat demo\showcases\control_baseline.json 120 scenarios\default.json

The default fleet showcase keeps its EcaA9 patrol at 100 m display depth so the AUV remains observable and responds quickly without commanding the 199 m seabed region.

Tuning Rules

Change one controller family at a time and keep waypoint speed below the documented baseline until the state topic shows stable tracking. Treat a new airframe or hull mass, inertia, actuator cap, or coordinate convention as a new baseline-validation event. Verify both the parser unit test and the eight-vehicle baseline sweep before promoting a change to a demonstration package.
