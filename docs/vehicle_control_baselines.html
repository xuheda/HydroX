Purpose

The shipped vehicle parameters are conservative baseline values for repeatable waypoint following in the three-domain demonstration. They are intended for integration, mission, and UI validation rather than aggressive handling or system-identification work.

Parameter Loading Contract

HydroX loads exactly one explicit VehicleBundle per process through --vehicle-bundle. Bundles live under profiles/<bundle>/vehicle-bundle.json and must use schema 2.0; the loader rejects old parameter files, parameter directories, missing fields and vehicle-type fallback.

The Bundle's control_model is the runtime source of truth for controller gains, limits and logical actuator layout. Its archetype groups are slender_body_fin, thruster, surface, multirotor, fixed_wing, vtol and differential_drive. ROV thruster limits and axis response are both explicit, and unactuated axes are represented by zero values.

OceanX owns the physical plant files under engine/Content/Fossen, engine/Content/Aero and engine/Content/Ground. Those files describe mass, inertia, hydrodynamics/aerodynamics, ground dynamics and collision behavior; they do not override HydroX control parameters. No inertia-based gain normalization or missing-group fallback is applied at Bundle load time.

Baseline Sweep

demo/showcases/control_baseline.json starts all eight per-vehicle planners, waits strictly for state/action readiness, and sends non-conflicting looping routes. Use it after bringing up the three-domain scenario:

demo_showcase.bat demo\showcases\control_baseline.json 140 scenarios\default.json

Strict state/action readiness for all eight vehicles can consume roughly 60–70 seconds, so a 120–140 second metric window is recommended. Set OCEANX_TRUTH_DIAGNOSTICS=1 to record plant truth beside estimated state without changing the normal feedback path.

The software HITL result validates the PC plant/bundle/control path only: no real FMUv6C was enumerated on 2026-08-07, so firmware, UART/DMA, timing, and physical I/O remain hardware acceptance work.

Tuning Rules

Change one controller family at a time and keep waypoint speed below the documented baseline until the state topic shows stable tracking. Treat a new Bundle, airframe or hull mass, inertia, actuator cap, or coordinate convention as a new baseline-validation event. Verify test_vehicle_bundle and the eight-vehicle baseline sweep before promoting a change to a demonstration package.
