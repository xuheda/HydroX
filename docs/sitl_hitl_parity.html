SITL / HITL 一致性契约

更新日期：2026-09-19

返回 HydroX 文档首页 · OceanX HITL 路线与台架 · 真实飞控台架操作手册

本文是 HydroX 软件在环与硬件在环行为对齐的权威说明。目标是让两种部署只在平台和传输边界上不同，估计、控制、权限和故障语义保持一致。

共享控制链

SITL 与 HITL 都执行同一个 runtime::HilSessionDriver 和 runtime::HilRuntime：前者统一连接 generation、传感器时间戳 epoch、暂停/恢复、维护与撤权后的输出要求，后者统一 EKF → feedback selection → GNC → allocator → arming/failsafe。SITL 额外提供 TCP、DDS、QGC、XLog 和可选实验服务；HITL 使用 NuttX clock、serial ByteStream、硬件 watchdog，并禁止物理执行器输出。这些平台差异不得复制或改写会话或控制语义。

多域保护的当前发布差异

SITL 与 FMUv6C 均强制使用 VehicleSupervisor → VehicleFailsafeNavigator → CommandArbiter 生成并授权参考；旧旁路和 Shadow/Active 启用开关已删除。硬件输出禁止仍保留，代码统一不等于真机台架验收完成。

AUV/ROV 受控上浮，USV 停车后在定位可用时守位，地面车制动；多旋翼及悬停 VTOL 保持，固定翼和巡航 VTOL 盘旋。空中不自动返航、不自动降落。VTOL 前/后转换受控恢复悬停，切换来源不重置实际阶段。详见 策略与验证边界。

地理保持需要最近 3 s 内 EKF 接受的水平位置观测，垂向控制需要最近 1 s 内接受的垂向观测；接收窗口使用平台单调时间。无定位时降级控制，不伪称定点；完全失去控制所需垂向观测或状态非有限时禁止输出。输出禁止不等于物理安全恢复。

Setpoint 数据契约

SITL 的 DDS CDR 输入和 HITL 的 companion command frame 在映射为 GNCSetpoint 后都调用 valid_gnc_setpoint()。最终运行时还会再次验证，任何入口都不能绕过该检查。

字段入口 sanity 上限
depth / down绝对值不超过 12000 m
heading绝对值不超过 1000 rad
surge speed绝对值不超过 100 m/s
yaw rate绝对值不超过 100 rad/s
waypoint north/east绝对值不超过 10,000,000 m

允许模式为 DISABLED、DEPTH_HOLD、WAYPOINT_3D、DP 和 SURFACE。这是协议枚举集合，不代表每种构型都支持：空中/地面拒绝 SURFACE，DP 只接受推进器式 UUV。上述值是拒绝损坏数据的协议上限，不是车辆允许运行包线；实际任务仍受 controller、allocator 和载具配置限制。DDS 使用 double，板端 command frame 使用 float32，因此线级精度不同，但有效性和安全语义一致。

连接、暂停与恢复

事件统一行为
新连接创建新 generation，清除旧命令；先收到本代有效传感器，再接受新命令。
断线立即撤销 actuator authority，进入安全输出。
仿真暂停立即撤销命令并输出零值/unarmed 控制，不等待超时。
仿真恢复创建新 generation；保留估计器内部状态，但必须重新收到传感器和之后的新命令。
外部命令超时/释放两端均短时 CommandHold 后锁存并按构型保护；明确释放可直接 Stabilize。接管期间传感器超时仍会触发输出禁止。
传感器超时撤销输出授权并锁存；旧样本不能跨 generation 恢复控制。
可控保护态显式接管新鲜参考、传感器和导航满足条件后调用 resume_external_control；SITL GCS 对应 DO_PAUSE_CONTINUE(param1=1)，不先 disarm。

OceanX UE bridge 采用相同的 connection generation 和 sensor-ready 门控，并校验 MAVLink CRC、HIL enabled、armed、heartbeat 与 actuator freshness。

车辆配置一致性

VehicleClass 必须与 VehicleArchetype 匹配；UUV、USV、multirotor、fixed-wing、VTOL 和 differential-drive 均由共享验证函数检查。生成的 FMUv6C 注册表当前包含十个 profile：generic-auv-fin、EcaA9、LAUV、DesistekSaga、RexROV2、VRX_WAMV、X500、RCCessna、StandardVTOL 和 R1Rover。每个 OceanX 载具 profile 用 hitl_profile_id 绑定其中一项；R1Rover 的 SITL 与固件统一读取同一个 vehicle bundle。

tools/hitl_bench.ps1 schema 2.0 按场景载具逐一重算精确字节 FNV-1a、SHA-256 和长度，校验注册表、bundle 与显式 HITL 动力学契约，再向每个 Router 传入各自的 ID/指纹。Router 在连接 UE 前向板端发送带 nonce 的 profile selection；板端只有在精确匹配或成功切换到已编译 profile 后才返回 READY。异构载具不再共享一个全局 profile 假设；修改任一已编译 profile 后仍必须重新生成注册表并重刷固件。

Profile 与 Session 配置契约

Profile 只拥有车辆类别、控制器、分配器、电机、估计器调参与传感器标定；Session 只拥有本次运行的初始 NED 状态、GPS 原点、周期/超时、任务半径、加速度模式和反馈策略。Setpoint、模式和 Arm 属于运行时命令；COM/TCP、DDS、QGC 与日志路径属于平台部署参数。各字段不得跨层静默覆盖。

HilSessionConfigV1 使用 76 字节固定顺序、小端、定点 canonical payload。距离使用毫米，经纬度使用 deg × 1e7，角度使用微弧度，时间使用微秒。身份为 SHA-256("OceanX/HIL_SESSION_CONFIG/V1" + profile_fingerprint + canonical_payload)；nonce 只绑定本次握手，不进入稳定配置身份。

启动顺序固定为 PROFILE_SELECT → PROFILE_READY → HIL_SESSION_CONFIG → HIL_SESSION_STATUS/READY → UE bridge。Session Config 使用自定义 MAVLink 消息 11067，状态使用 11068；旧固件忽略新消息后 Router 超时并拒绝开放 UE，不允许静默使用板端默认值。板端将新配置暂存后先撤权、发送安全输出并销毁旧 runtime epoch，再由入口重新构造 SensorAdapter、EKF、Controller、Allocator、HilRuntime 和 HilSessionDriver；只有新实例可以发送 Session READY。

SITL 与 HITL 最终都调用 resolve_hil_session_config() 和 apply_hil_session_config()。HITL 场景中的 vehicles[].location（NED 米）、rotation（RPY 度）和可选一次性初速提供初始状态；周期、超时、GPS 原点和策略来自独立的 configs/hitl_sessions/*.json，由台架 session_profile 选择，启动器将两者合并为线上 Session Config。Release 板端拒绝 truth_debug、truth heading aid 以及尚未具有 Profile capability 声明的非零 sensor mask。

控制轨迹与 XLog 统一

SITL 记录器和 HITL Router 现在写入同一套 XLog topic：Setpoint、Timing、ControllerOutput、Actuator 和带提交标记的 State。两种来源都携带 Profile ID、精确 fingerprint、canonical Session payload 与 session digest；因此同一个 control_shadow 可以对 SITL 和 HITL 日志执行相同的控制器/分配器重放与逐 tick 对比。XLog Reader 对 CRC、schema、序号、分段身份和截断尾块执行同样的严格/恢复策略。

HITL 的板端通过 MAVLink HIL_CONTROL_TRACE（消息 ID 11070）在每个有效控制 tick 发送完整输入快照：测量时间、状态、Setpoint、控制输出、Setpoint 年龄、模式、mission、权限/撤权、reset、DVL/EKF 来源和 truth 使用标记；随后 Router 将同 tick 的标准 HIL_ACTUATOR_CONTROLS 合并到 XLog。这样串口传输不会改变 SITL 的回放边界。Release HITL 不产生 simulator truth，used_truth 必须为 false；若调试构建启用 truth，仅可作为诊断字段，不能成为控制输入。

Router 支持 --xlog auto|<path> 和 --stop-file <path>。台架默认使用每车独立的 control-*.xlog，收到停止请求后先停止发命令、刷新 footer 和统计，再退出；缺少或损坏日志会让本次采集失败，不得被静默视为成功。

固件构建边界

所有 HITL 固件入口共用 cmake/hitl_core_sources.cmake，避免独立 CMake 目标与 NuttX external 应用漏编不同控制器或编解码器。实际 FMUv6C / Pixhawk 6C Mini 集成位于 boards/fmu_v6c 和 nuttx_apps/external/hydrox_hitl，包含 NuttX defconfig、UART DMA、IWDG、早期 PWM 输出抑制和 PX4 制品打包定义。

build_pixhawk6c_hitl.bat 已转接当前 FMUv6C NuttX external 构建；旧独立 BSP 占位入口已删除，独立 CMake 构建仅支持 HYDROX_TARGET=HOST。现用 FMUv6C 路径仍需完成 6C Mini 实板 bootloader 传输、回滚和台架验证。

已知且保留的差异

差异原因与后续动作
SITL 可在运行前直接读取 profile JSON；板端 profile 注册表编译进固件台架已按载具选择并做运行时精确握手，但 profile 内容变化仍需重新生成注册表、构建并刷写固件。
SITL 由进程参数适配器读取 Session；HITL 由 Bench 场景适配器读取 Session外部载入方式保留平台差异，但两者必须进入同一 resolver/mapping；HITL 额外通过 profile-bound SHA-256 与 nonce 做板端确认。
DDS double；companion frame float32保留传输精度差异，持续共用校验和单位。
PC 支持 DDS、QGC、XLog、MAVLink signing；嵌入式不全部启用这些是平台服务；嵌入式签名需安全密钥存储后才能启用。
硬件调度、串口、watchdog 和 bootloader交叉构建只覆盖静态边界；实际传输、时序和故障行为仍只能由实机台架验证，不能由主机单元测试替代。
