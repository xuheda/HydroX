定位

本文是 OceanX 与 HydroX 当前 ROS 2 Topic、Service、Action、QoS、发布频率、坐标系和新鲜度规则的唯一权威说明。HydroX 控制器、估计器和分配器本身见 HydroX 控制架构；ROS package 的构建与启动见 ROS 2 工作区说明。

接口定义分为三层，修改时必须同步：

  1. ros/src/oceanx_interfaces/{msg,srv,action}/ 定义字段和 ROS 类型。
  2. HydroX/include/dds_topic_manifest.h 定义 bare XRCE-DDS 话题的名称、方向、类型、ID 和发布频率。
  3. 本文定义端到端语义、Owner、消费者、QoS、frame、超时与安全边界。

快速理解

ROS 任务 / 策略 / 操作员
  -> /oceanx/{vehicle}/control/setpoint_sources/{source}
  -> setpoint_mux
  -> /hydrox/{vehicle}/in/setpoint
  -> HydroX GNC / allocator
  -> MAVLink HIL_ACTUATOR_CONTROLS
  -> UE / OceanX dynamics

UE 传感器 / Fossen 或 Aero 状态
  -> MAVLink HIL
  -> HydroX estimator
  -> /hydrox/{vehicle}/out/*
  -> ROS 控制、协调、诊断与可视化

{vehicle} 是场景和启动配置中的稳定载具名，例如 ecaa9_test。同一载具的所有节点必须使用完全相同的名称和 ROS_DOMAIN_ID。

VehicleState 是平台中性的六自由度状态消息；/out/state_estimate 发布导航估计，/out/truth_state 仅发布显式开启的仿真真值。文档中的普通对象称谓统一使用“载具”。

控制源仲裁

setpoint_mux 是 /hydrox/{vehicle}/in/setpoint 的唯一 ROS Publisher。默认请求源是 disabled；选择 auto 时，从仍然新鲜的 source 中按下表选最高优先级：

Source优先级典型生产者
manual80direct_cmd_adapter / teleop
diagnostic70parity_diagnostic
formation45formation_follower
waypoint40waypoint_planner

mux 只缓存状态恢复之后收到的新命令。估计状态消息 VehicleState 失联、字段非有限或 source 超时都会清空缓存并发布新的 DISABLED 命令；恢复顺序必须是“先收到新状态，再收到新 source command”，禁止重放失联前命令。

所有安全相关 age 使用消费者本地单调接收时间。header.stamp 用于追踪和数据对齐，不证明远端仍存活。

坐标系与 frame_id

  • 世界位置、世界速度、姿态表达和 waypoint 使用 NED，单位为 SI。
  • 机体线速度、角速度、IMU 和执行器使用 body FRD。
  • VehicleState、truth、odometry parent 和 TF parent：map_ned。
  • 机体量、odometry child 和 TF child：{vehicle}/base_link_frd。
  • receiver-local 声呐和 rangefinder：{vehicle}/base_link_frd。

Odometry 和 TF 数字本身就是 NED/FRD。ENU/FLU 消费者必须通过 tf2 或显式转换改变数值；只把 frame_id 改成 world、odom 或 base_link 属于协议错误。

AcousticNeighbors 当前字段限制

当前 HIL payload 每个 contact 实际传输 sender_id、range、propagation delay、depth、NED position、NED linear velocity、yaw_ned_rad 和前三个 payload 值。接口不再伪造 roll/pitch 或角速度零值；若未来传输完整姿态/角速度，必须新增具有明确 frame 的字段，并同时修改 HIL payload、HydroX parser/writer、消息注释、本文和序列化测试。

Service 与 Action 生命周期

  • FollowWaypoints 是静态航点任务的权威生命周期；上层使用 result 释放载具，不从可能滞后的 VehicleState.mission_state 推断任务完成。
  • AssignFleetMission 只在目标合法、载具状态新鲜且下游 Action server 可用时接受 Goal；取消会转发给对应 FollowWaypoints。
  • 多载具任务取消只有在下游终态确认后才正常释放载具。取消拒绝、通信失败或宽限期结束仍无终态时，载具进入隔离，直到迟到终态解除。
  • ManageFormation START 先校验完整配置、计算 slot 并创建新 ROS 实体，全部成功后才提交；失败不得破坏旧编队。
  • 单载具编队把任何有限非负 spacing 归一化为 0；多载具 spacing 必须大于 0。

ROS 名称与 DDS 名称映射

HydroX 使用 bare Micro XRCE-DDS。ROS 名称与 DDS 名称由 manifest 统一生成：

ROS: /hydrox/{vehicle}/out/state_estimate
DDS: rt/hydrox/{vehicle}/out/state_estimate

ROS: /oceanx/{vehicle}/out/acoustic_neighbors
DDS: rt/oceanx/{vehicle}/out/acoustic_neighbors

ROS: /tf
DDS: rt/tf

DdsPublisher 使用同一清单创建 topic、DataWriter/DataReader 和节流周期。新增 bare-DDS 接口不能只在 ROS 侧声明消息；还必须分配不冲突的 topic/endpoint ID、补齐 CDR 序列化和契约测试。

ros2 topic info --verbose /hydrox/vehicle0/out/state_estimate

与 XLog 的区别

/hydrox/state、/hydrox/setpoint、/hydrox/control_error、/hydrox/controller_output、/hydrox/actuator、/hydrox/estimator_health 和 /hydrox/timing 是 XLog 1.0 内部 stream 名，不是 ROS 2 Topic。XLog 格式、分段和回放边界见 OceanX 回放、rosbag 与 XLog。

维护规则

  • 新增、删除或重命名任何 Topic、Service、Action 时，同一变更必须更新本文。
  • bare-DDS 接口必须同步更新 dds_topic_manifest.h、CDR writer/reader、ROS interface 和测试。
  • 发布频率只在 manifest 或节点参数默认值中定义；本文记录并解释，不再在控制架构文档复制整张表。
  • 任何安全相关订阅都必须明确 QoS、receive-time freshness、timeout 和恢复顺序。
  • 任何新世界/机体字段都必须明确 NED、ENU、FRD 或 FLU；不得只靠字段名猜 frame。
  • 调试 truth 和 visualization 派生数据不得成为控制、估计或物理的权威来源。
