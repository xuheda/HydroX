目标

Stage 2 的目标是让 HydroX 成为独立飞控软件。HydroX 不依赖 PX4 或 ArduPilot 的运行时架构；当前固定使用 Apache NuttX 13.0.0 作为 RTOS 与 STM32H7 平台基础，并由 HydroX 维护 Pixhawk 6C 板级移植、平台适配、运行时和控制栈。

  • 算法不得包含 Windows、POSIX、NuttX、STM32 或 Pixhawk 头文件。
  • platform/api 不依赖操作系统或板卡。
  • platform/nuttx 只封装 NuttX，不保存 Pixhawk 6C 引脚和设备映射。
  • boards/pixhawk6c 只负责启动、内存、引脚、总线、DMA 和设备注册。
  • apps/pixhawk6c_hitl 只组装运行时，不实现驱动或控制算法。

命令 freshness 与 timeout 始终使用 HydroX 平台单调时钟，保证暂停、回滚或慢放不会延长命令权限。导航估计、制导控制和执行器模型则统一使用输入 measurement timestamp；仿真链路由 HIL 消息承载该时间戳，真实传感器驱动遵循相同契约。

OceanX 已提供 -OceanXRunMode=hitl：不自动启动本机 hydrox_sitl 或 DDS Agent，强制 RTF 1，并在每次连接或暂停恢复后先发送当前 HIL_SENSOR，再接受执行器权限。HITL Router、共享运行时和 Pixhawk 应用监督循环已经实现；当前剩余硬件边界是 Pixhawk 6C BSP、UART/USB 驱动、已验证链接脚本和可烧录固件。

当前完成状态

  • platform/api：时钟、等待、非阻塞字节流、临界区、任务、存储和看门狗契约。
  • platform/host：PC 时钟、等待器与临界区。
  • platform/nuttx：NuttX 时钟与等待器。
  • HydroBus：latest-value topic 与有界 SPSC 队列。
  • 共享运行时：固定周期调度、迟到/错过周期处理、连接代次、传感器就绪、旧命令拒绝和超时撤权。
  • SITL 已使用 Host 平台适配和共享运行时组件。
  • Pixhawk 6C HITL 入口已改成 NuttX 应用结构；真实 BSP 尚未完成，因此不会生成占位固件。
  • PC 构建当前注册 27 项 CTest，包含共享运行时、假板卡 HITL 端到端链路和真实入口链接检查。

下一步

  1. 完成 Pixhawk 6C 最小 NuttX 板级移植：控制台、状态灯、时钟、缓存和 DMA 内存。
  2. 实现 Pixhawk 6C 非阻塞 UART/USB、RK3588 指令源、看门狗和参数存储的真实 BSP 适配。
  3. 核验 bootloader 内存布局、缓存和 DMA 区域并完成上板烧录。
  4. 补齐板端日志、复位原因、硬件故障注入和 24 小时稳定性验证。
