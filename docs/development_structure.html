目标

Stage 2 的目标是让 HydroX 成为独立飞控软件。HydroX 不依赖 PX4 或 ArduPilot 的运行时架构；当前固定使用 Apache NuttX 13.0.0 作为 RTOS 与 STM32H7 平台基础，并由 HydroX 维护 Pixhawk 6C Mini / FMUv6C 板级集成、平台适配、运行时和控制栈。

  • 算法不得包含 Windows、POSIX、NuttX、STM32 或 Pixhawk 头文件。
  • platform/api 不依赖操作系统或板卡。
  • platform/nuttx 只封装 NuttX，不保存 Pixhawk 6C Mini 引脚和设备映射。
  • boards/fmu_v6c 负责当前启动、内存、引脚、总线、DMA、watchdog 和设备注册。旧独立 BSP 占位入口已删除。
  • apps/pixhawk6c_hitl 只组装运行时，不实现驱动或控制算法。

命令 freshness 与 timeout 始终使用 HydroX 平台单调时钟；SITL/HITL 默认均为 500 ms。导航估计、制导控制和执行器模型统一使用输入 measurement timestamp。暂停会立即撤权和输出安全零值；恢复会创建新 generation，必须先收到新传感器、再收到新命令。完整规则和输入上限见 SITL/HITL 一致性契约。

OceanX 已提供 -OceanXRunMode=hitl：不自动启动本机 hydrox_sitl 或 DDS Agent，强制 RTF 1。HITL Router、共享 runtime、NuttX supervisor、UART ByteStream、IWDG、FMUv6C board integration 和固定交叉构建/静态包校验已实现；剩余边界是实板 bootloader 传输、烧录回滚和台架资格验证。

当前完成状态

  • platform/api：时钟、等待、非阻塞字节流、临界区、任务、存储和看门狗契约。
  • platform/host：PC 时钟、等待器与临界区。
  • platform/nuttx：NuttX 时钟与等待器。
  • HydroBus：latest-value topic 与有界 SPSC 队列。
  • 共享运行时：固定周期调度、连接代次、传感器就绪、500 ms 超时、setpoint 范围、暂停/恢复撤权和安全输出。
  • SITL DDS 与 HITL companion command frame 共用最终 GNCSetpoint 验证。
  • FMUv6C NuttX external 应用、双 UART、IWDG、reset reason、早期 PWM 抑制和制品打包定义已提交。
  • 所有 HITL 构建入口共用 cmake/hitl_core_sources.cmake。
  • PC 构建当前注册 54 项 CTest，包含共享 runtime、暂停/恢复、输入边界、假板卡 HITL 端到端链路、控制器和 profile 指纹检查。
  • 固定 NuttX 13.0.0 + Arm GNU 13.3.Rel1 可生成并校验 FMUv6C ELF/BIN/HEX/MAP/PX4/manifest。

下一步

  1. 在断开全部执行器的 Pixhawk 6C Mini 上完成 bootloader 传输、启动与原厂固件回滚演练。
  2. 实板核验 flash/RAM、缓存和 DMA 区域行为。
  3. 验证 UART5 流控、UART5/UART7 双向 DMA、UART7 三线链路、USB console、IWDG reset、复位原因和安全输出。
  4. 未来计划（尚未实现）：从 VehicleBundle 自动生成板端 profile，并增加部署时 profile 指纹握手。
  5. 完成故障注入、吞吐/抖动测试和 24 小时稳定性验证。
